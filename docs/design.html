UI/UX Design Constraints — Bike Purchase Leads Management System

Version: Draft for review  |  Date: 2026-10-17
Design guidance: impeccable (Operate mode), frontend-design restraint, responsive-design mobile-first, taste anti-slop. Note: the design-taste-frontend skill declares itself "not for dashboards or app screens," so it does not apply to this dashboard UI.

1. Visual Direction

  • Clean, minimal, professional operations tool. No F3 Motor brand colors required.
  • Mode is Operate: scanability and consistency outrank expression. One restrained surface, quiet chrome, content (lead cards, counts) carries the page.
  • Light theme only for MVP. System font stack. One sans family; clear size hierarchy (page title → section → card title → body → secondary).
  • Flat surfaces separated by small tone steps; no gradients, no glows, no glassmorphism, no violet/indigo accents, no emoji icons, no all-caps micro-labels.
  • Buttons: flat, one fill color for primary, decided once and reused everywhere.

3. Accessibility Requirements

  • Target WCAG 2.1 AA for an internal tool: visible keyboard focus on all controls, sufficient tag text contrast (dark text on tints), real <button>/<a> elements.
  • Carousel has labeled prev/next controls and alt text per photo; status dropdown is keyboard-operable.
  • Touch targets at least 44×44px on mobile; motion respects prefers-reduced-motion.

4. Component Philosophy

  • Global/shared components → /components/global/ (buttons, tags, pagination, toasts, skeletons).
  • Route-specific components → /app/<route>/_components/ (lead card, pipeline tabs, dashboard stats).
  • Check for an existing reusable component (grep SOT keywords) before creating a new one.
  • shadcn/ui primitives first (decision D6, confirmed): install via npx shadcn@latest add into /components/ui/; compose app UI from them instead of custom markup. Follow the shadcn skill rules: semantic colors only, built-in variants before custom styles, cn() for conditionals.
  • Icons: lucide-react only, per the shadcn icon rules (data-icon in buttons, no sizing classes inside components).

5. Interaction Patterns

  • Status change: immediate UI update with server confirmation; on failure, revert and show an error toast.
  • Loading: Skeleton cards while lists load; Spinner + disabled on buttons for mutations.
  • Errors: sonner toasts naming what failed and how to retry; never raw stack traces. Inline form errors via Field + data-invalid.
  • Empty states: the Empty component on each list/tab ("No qualified leads yet — new imports land in All Leads.").
  • Delete: always behind an AlertDialog naming the lead.
  • Search: debounced; filters and search combine; pagination resets to page 1 on any filter/search change.

6. Layout and Responsiveness

  • Mobile-first. Card grid: 1 column on phones → 2 on tablets → 3–4 on desktop, driven by content width.
  • Top nav: Dashboard · All Leads · Pipeline · Import · Logout. Collapses to essential links + menu on small screens.
  • Pipeline tabs scroll horizontally on narrow screens; dashboard stat cards wrap.
  • No horizontal overflow at 360px width; images keep aspect ratio, never stretch.
